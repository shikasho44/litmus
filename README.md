# リトマス審問（旧題: ジェーンドゥの死因）

名前を失った女性の魂「ジェーン・ドゥ」が、どうして死んだのか。
プレイヤーは死因審問官になり、案内役ホルマ（白ウサギの剥製標本。片目は琥珀色のガラス玉）に**はい／いいえで答えられる質問を自由に打ち込んで**真相を探ります。
彼女の記憶の中で光る「誤差」に、集めた所見をリトマス試験紙のように当てて正し（反証）、自分の言葉で死因を宣告し、5コマ漫画で真相を組み直します。
解決すると彼女の名前と顔が戻り、その死の裏にある科学を図解で学び、確認テストで記憶に定着させて、審問官ランク（S/A/B/C）と名探偵度数（事件ごとの最高の合計。称号バッジつき）を受け取ります。ミスをすると、その場で「減点」が見えます。

- ブラウザで遊ぶ（PC・スマホ）。知的で少し不穏で上品。血やグロテスクな描写はしません。
- 事件は8件。はじめに、**身近な出来事で人が亡くなる、短いチュートリアルの1件**（2026-09-29 追加。約12分、審問は1ラウンド、こわい場面なし）:
  **CASE 01「たたみかけのタオル」**（c08。洗濯物にひそんだハチの「二度目のひと刺し」によるアナフィラキシー）。
  つづいて、**人ではなく「もの」の死因をさぐる短い入門の3件**（2026-09-28 追加。各10〜15分、審問は1ラウンド、こわい場面なし）:
  **CASE 02「背のびした牛乳びん」**（c05。水は凍ると大きくなる）／**CASE 03「氷点下の雪だるま」**（c06。黒いマフラーが日の光を吸う）／**CASE 04「水のそばの渇き」**（c07。人かどうかも分からないところから始まる。真相は水を吸えなくなったバラ）。
  そして本編の4件: **CASE 05「息のない部屋」**（c01。液体窒素による酸素欠乏）／**CASE 06「夕暮れの白球」**（c02。心臓震盪）／**CASE 07「雪に残されたもの」**（c03。低体温症と矛盾脱衣）／**CASE 08「白い花の夕餉」**（c04。山菜の採り違えに見せかけたトリカブト中毒。初めての殺人事件）。
  事件の id（c01〜c08）と画面の番号（CASE 01〜08、`case.json` の `number`。ジェーン・ドゥの番号 #01〜#08 も同じ）は別物です。遊び方の案内（コーチマーク）は CASE 01 の初回で出ます。すべて架空です。
- 質問の判定は、事前に書いた事件データを正本として、判定専用の軽いAI「Jev」が行います。返事の文章は書き溜めた台詞から選ぶので、AIが真相を漏らしたり話を作ったりしません。

> 開発の記録と引き継ぎは **`docs/handover.html`**（ブラウザで開く1枚のノート）から始めてください。

## 1. 動かす（自分のPCで遊ぶ）

必要なもの: Node.js 24（`node -v` で確認）。

```bash
npm install          # 最初の1回だけ
npm run dev          # 開発サーバーを起動
```

ブラウザで **http://127.0.0.1:5190/** を開きます。止めるときはターミナルで `Ctrl + C`。

- 管理画面（事件データの検査・質問テスト・判定の記録・ベンチ結果）: **http://127.0.0.1:5190/admin.html**
- 開発サーバーは、`OPENROUTER_API_KEY` があれば **Jev モード（有料・ごく安い）**、無ければ **rules モード（無料・オフライン）** で動きます。無料で試したいときは `.env.local` に `PIPELINE_MODE=rules` と書きます（§4）。
- 画面のデバッグ用の道具: URL の末尾に `?debug=1` を付けると、開発者ツールのコンソールで `window.__JD` が使えます（場面へのジャンプなど。`docs/frontend.md` §7）。`?mute=1` で音なし。

## 2. 遊んで確かめる（プレイテスト）

1. タイトル → 「審問を始める」→ 初回はプロローグ（スキップ可）→ 事件ファイルで事件を選ぶ。
2. 捜査: 下の入力欄に質問を打って Enter。例「彼女は一人でしたか？」「部屋に窓はありましたか？」。
   困ったら入力欄の上の**質問の例**のカード（捜査の時間とともに届く。見習い・審問官は2枚から＋1分ごと、教授は2分後から。並ぶのは3枚まで。`src/features/examples`）、または右上の「ホルマの囁き」（ヒント3段階。ランクが少し下がる）。
   質問には難易度ごとの**質問枠**がある（入力欄の上の札「残り n/N」。審問官は超えると減点、教授は使い切ると締切。「具体的に」や雑談は数えない。事件ごとの数は各 case.json の `questionBudget`、規則は `shared/budget.ts`）。
3. 「審問を開く」→ 反証（光っている誤差に所見を当てる。正しければ赤が青に変わって「反応あり！」）→ 死因宣告（自由記述）→ 真相再構成（コマ漫画）。
4. 身元回復 → 科学解剖 → 記憶の定着（確認テスト）→ 結果。結果には解決タイムと、その事件の**初回の解決**（最初の1回だけ記録され、上書きされない）。事件ファイルの見出しに「初見タイム合計」。

**スマホで試す**: 開発サーバーはこのPCの中からしか開けません（安全のため）。同じWi-FiのスマホからPCに繋ぐときは、
`npx vite --host 0.0.0.0` で起動し、スマホで `http://<PCのIPアドレス>:5190/` を開きます（終わったら止めること）。
開発サーバーは管理画面が鍵なしで開き、Jev モードなら質問ごとに費用もかかるので、**自宅など信頼できる Wi-Fi でだけ**使ってください。
本番に近い形で試すなら、公開中の Cloudflare 版（https://litmus.fourthplace43.com/）か Vercel のプレビュー配備が確実です（`docs/DEPLOY.md`）。

**途中から試す近道**（開発サーバーのみ）: 管理画面の「トークン」で、捜査済み・審問突破・解決済みなどの段階まで進めた状態を作れます（`POST /api/admin/mint-token`）。
セーブはブラウザの localStorage に入ります。最初からやり直したいときは設定画面の「記録をすべて消去」。

**人に遊んでもらうときに見てほしいこと**: 詰まった場所（5問以上続けて「関係ない」「具体的に」が返る）／ヒントを使ったか／審問の2ラウンド目で「泣きつき」が必要だったか／同じ意味の質問に違う答えが返ったか／スマホで押しにくいボタン。AIプレイテストでは分からないのがこの部分です（`docs/playtest-report.md` §9）。

## 4. 環境変数（`.env.local`）

`.env.example` をコピーして `.env.local` を作り、値を書きます。**`.env.local` は git に入りません。APIキーを commit しない・チャットやスクリーンショットに貼らないこと。**

| 変数 | 意味 | 開発機の目安 |
|---|---|---|
| `OPENROUTER_API_KEY` | Jev（と任意の LLM）を呼ぶキー。サーバーだけが読み、ブラウザには出ない | 空なら rules モード |
| `SESSION_SECRET` | 進行トークンの署名鍵。**本番は32文字以上の乱数が必須**（無いと本番は 503 で止まる） | 開発では空でよい |
| `PIPELINE_MODE` | 判定のしかた（下の表） | `jev` または `rules` |
| `DAILY_COST_LIMIT_USD` | 1日（UTC）あたりの費用上限（サーバー1台ごと）。超えたら無料の rules に自動で落ちる | `1` |
| `ADMIN_TOKEN` | 本番の管理画面のパスワード（32文字以上）。空なら本番の管理 API は無効 | 開発では不要 |
| `JEV_CANDIDATES` / `JEV_PROMPT` | 判定の細かい設定（既定 `all+prior` / `v2`） | 触らない |
| `LLM_PROVIDER` / `LLM_MODEL` | 返事の言い換えに LLM を使うとき（比較用） | `none` |
| `VITE_*` | 画面側の設定（タイトル、公開URL、正式公開フラグ、管理画面を含めるか）。ビルド時に読まれる | `.env.example` 末尾を参照 |

全項目の説明は `docs/engine.md` §7 と `docs/ai.md` §6。

## 5. 判定のモード

| モード | 中身 | 1問の費用 | 使いどころ |
|---|---|---|---|
| `rules` | 想定質問との類似＋キーワードだけ。外部API なし | 0円 | オフライン・静的版・自動テスト・障害時の退避先 |
| **`jev`（既定）** | Jev が判定 → 書き溜めた台詞で返事 | 約 **0.045円**（$0.0003） | **本番**。正答率 91.1%（rules は 73.4%） |
| `jev+llm` | Jev が判定 → LLM がホルマ口調で言い換え | 約0.02〜0.06円 | 表現の比較（遅くなる） |
| `jev+llm+check` | 上に加えて Jev が言い換えを検査 | 約0.02〜0.06円 | 言い換えを使うならこちら |
| `llm` | LLM が全部判定（真相を渡す） | 約0.04円 | 比較の基準線。**使わない**（正答率が低く、話を作る） |

- 数字は 2026-09-25 の実測（823問・leave-one-out。`docs/ai.md` §0・§5）。為替は 150円/$。
- 死因宣告の判定は1回 約0.01円。1万問で 約450円（既定の設定）。`JEV_CANDIDATES=topk+prior` にすると費用は約1/4、正答率は約3〜4ポイント下がる。
- Jev が失敗・遅延したときは、その1問だけ rules で答え、画面に小さく「簡易判定」と出ます。ゲームは止まりません。

## 6. 事件を足す（コードの修正は不要）

1. `content/cases/<新しいid>/case.json` を置く（形式は `shared/case-schema.ts`。既存の3件を手本にする。`id` はフォルダ名と同じ）。
   画像は `public/cases/<短いid>/`（背景・肖像・再構成のコマ4〜6枚。**画像の中に文字を入れない**）。
   被害者が人でないときは `victim.silhouette`（破片の型。`scripts/art/trace_silhouette.py` で肖像から取れる）と `victim.profile`（名前の下の行。年齢・職業の代わり）を書きます。肖像が少しずつ見えるだけで正体が分かってしまう事件は、解くまで破片に映す絵を `victim.shardPortrait` で差し替えられます（c07）。
2. `npm run validate` を実行し、エラーが 0 になるまで直す（警告は通る）。
   検査内容: 形式、ヒント3つ、答えの要素、出典3件以上、公開してよい文に答えの語（`leakTerms`）が無いこと、想定質問との自己一致率95%以上 など（`docs/engine.md` §4）。
3. `npm run dev` で遊んで確かめる。`publish: false` の間は本番の一覧に出ません。
   試作の事件は `"proto": "seeds"` を付けると、URL に `?proto=seeds` を付けたときだけ出ます（dev・本番・静的版・Cloudflare とも。2026-10-04 の「助けられた朝」c09 がこれ。`shared/proto.ts`、`docs/decisions.md`）。I-001 リトマス・ラボ（仮の名前。2026-10-04 に「ツクール」から改名）の見本3問（c10〜c12、絵なし）は `"proto": "lab"` で、`?proto=lab` のときだけ出ます（`docs/ideas/I-001-samples.html`。古い `?proto=tsukuru` もしばらくは同じ意味で通ります）。
4. `npm test` と `npm run qa -- --case <id>` を通す。書き方の決まり（ホルマの口調・安全の配慮）は `content/VOICE.md`。

科学解説は人の専門家が確認するまで `reviewStatus` を `ai-reviewed` のままにします（画面に「専門家確認前の下書き」と出ます）。

## 8. 大事な注意

- 題名は 2026-09-26 に「ジェーンドゥの死因」から **『リトマス審問』** に変えました（元の名前は薬理凶室さんの企画と重なるため。くられ先生からの返信による）。作中の「ジェーン・ドゥ」という呼び名を変えるかは確認中です。正式公開までは `VITE_OFFICIAL_RELEASE_ENABLED=false`（PREVIEW 表示・検索エンジンに載せない）のままにします。名前は `VITE_APP_TITLE` などで差し替えられます。
- 科学解説は AI が公的資料で裏を取った下書きで、**人の専門家の確認前**です。
- 静的版（`build:static`）は事件の答えをすべてブラウザに同梱します。答えを守りたい公開には API のある版（Cloudflare 版・Vercel 版）を使います。
