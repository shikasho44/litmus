## 1. 設計意図

- **公平さ**: 核心（酸素欠乏）に至る伏線を、別々の方向から重ねた。

- **人を疑う判断の問い**（「その学生は怪しい？」）は `vague`（証拠の形で訊き直してもらう）、**人や動機が死に関わったか**（「もう一人の人は関係ありますか？」「口論は関係ありますか？」「大学院生のせいですか？」）は `cannot`。どちらも manner.ts が拾わない言い回しなので想定質問で止めた（note に理由）。「同僚との口論は死因に関係ありますか？」は irrelevant → cannot に変えた（「関係ない」だと動機の筋が一問で消える）。

- **ホルマの「壊れた機械」**: 設計書の「壊れた機械」は、故障ではなく **電池切れ**（点検の不備）にした。安全装置は置いてあるだけでは意味がない、という教訓に直結させるため。

## 2. 真相（1段落）

0時52分、液体窒素保管タンクの液面低下警報がスマホに届き、白石澪（29・特任研究員）は一人で地下の試料保管室へ。1時25分ごろ、大型の自加圧式供給容器からホースで補充を始め、待つあいだ、タンクに背を向けて細胞の箱を点検。補充中はもともとタンクの口から気化した冷たい窒素と白い霧が出続けるため、1時40分ごろタンクが満杯になってあふれ始めても見分けにくく、彼女は気づかない（2026-09-25 の科学再検証で追加。「六畳の部屋にいて約20分もあふれに気づかないのはなぜか」という穴を埋めるため。入館記録とカメラ（F09）を変えずに済む形を選んだ）。弁は開いたままで、あふれた液体窒素が床で気化し続けた。気化したばかりの冷たい窒素は重く、まず床の近くにたまる。夜22時〜7時は省エネ運転で排気停止、防火扉は自動で閉まり、壁の酸素濃度計は電池切れ。窒素が小部屋の空気を押しのけて酸素の割合が下がり、2時前後、強い息苦しさを感じないまま判断力を失い、扉の近くの棚にもたれて座り込み（顔が床近くの最も酸素の薄い層に近づいた可能性）、意識を失って死亡。座った場所はタンクから離れていて、床に広がった液体窒素は届いていない（凍傷がない理由。F17 judgeNote・F19）。2時半ごろ供給容器がほぼ空になり流れが止まる。扉のすき間からの空気の入れ替わりはわずかで、6時4分、警備員が扉を開けて一歩踏み込み、声をかけるうちに急なめまい→すぐ廊下へ下がり、ドアストッパーで扉を開け放ったまま中へ戻らず救急要請（扉は手を離すと閉まる防火扉なので、開け放つ手段を明記。p5 の絵にもドアストッパーが描かれている）。

### 数量の整合（定性のみ。致死量・時間の計算は書かない方針）
- 補充開始から約15分でタンクが満杯になる流量なら、供給容器の中身はおよそ1時間ほどで流れ切る。そのため「明け方まで気化が続く」という初稿の記述をやめ、「2時半ごろ流れが止まる」に直した（科学査読の指摘）。
- 流れが止まった時点で、六畳ほどの部屋の空気は大きく置き換わっている。換気が止まり防火扉が閉じた部屋では、扉のすき間などからゆっくり空気が入れ替わるだけなので、発見時にも「危険だが、一歩で即座に昏倒するほどではない」状態が残っていた、という仮定で警備員のめまいと整合させた。査読では空気の入れ替わりの速さを仮定した検算をしたが、**数値はこのノートにも残さない**（安全査読の指摘。部屋の容積と液体の量から危険になるまでの時間を逆算できる情報は書かない）。
- 警備員が助かったのは「すぐ引き返し、二度と入らなかった」から。それでも運がよかった、と本文（F32 の judgeNote、foreshadowing、mechanism「助けに飛び込むと、二人目になる」）で明示し、「警告を感じてから下がれば大丈夫」という誤った教訓にならないようにした。
- 実例との比較: 職場のあんぜんサイトの災害事例 No.856 は、換気設備のない小実験室（本件の部屋よりずっと広い）で、液体窒素の充填中のあふれにより研究員が酸欠で亡くなった事例。後日の**再現実験**では、室内で最も酸素の低い地点の濃度が時間とともに下がり続け、災害時にはごくわずかになっていたと報告されている（具体的な時刻と濃度は出典を参照。初稿の「18分で18%…」は、再現実験の値であることと測定地点を書き落としていたため訂正）。

## 4. 難易度の根拠（難易度1）

- 最初の例チップで毒・病気はすぐ消える。他殺の疑いは死の種類の封印で「答えられない」まま残り、証拠（F09・F42・F43・F44・F45・F46・F11）で一つずつ消していく（2026-09-27 更新。以前は例チップだけで他殺も消えた）。それでも「部屋」に目が向くのは早い。
- 核心に向かう手がかりが多く（imp3 が6枚）、どこから入ってもつながる。
- 必須要素は3つ（A 直接死因・B 液体窒素・C 仕組み＝気化／押しのけ／充満／薄まり など）。「なぜ気づけなかったか」（D）は加点扱いで必須にしない。「液体窒素で酸欠」「液体窒素で酸素が減った」だけなら「ほぼ正解」で、ホルマが仕組みを一言促す。「液体窒素の気化で酸欠」なら正解（査読で C の判定語を整理し、A と同じ語で C が埋まってしまう問題を解消）。
- 審問の2ラウンドはどちらも一対一で論理が明快（「だれかが、わたしを閉じ込めた」⇔ F09 扉に近づいた者はいない（ほかに F28 鍵なし・F45 夜10時の巡回・F43 地下へ来なかった学生）／「壁の機械が鳴った」⇔ F31 電池切れ（ほかに F34・F33・F46））。ホルマの発言はどちらの回も「真実だが所見を当てる場所ではない」おとりにした（嘘を言わない掟のため）。r1 のおとり2つ（もう一枚のカード・外されたストッパー）は他殺の疑いをあおる役（§1-2）。持っていなくても「泣きつく」で詰まない。（2026-09-27 更新。以前の r1 の誤差は「だれかが後から入ってきた」）

### 数値の扱い
- 「約700倍」は室温付近の値（0℃の646倍を気体の温度膨張で換算すると約690倍）。図には「約700」を置き、注記で「0℃では約650倍」と明記した。
- 酸素濃度の閾値は厚労省リーフレットと千葉大学の表で一致する値だけを使った。死亡までの分数（リーフレットの「7〜8分」）や、二酸化炭素の中毒濃度は **意図的に書いていない**（「致死量・手順を書かない」方針）。
- 頸動脈小体の低酸素応答の閾値などの数値は書かない（定性的な記述のみ）。

## 6. 安全面の配慮
- 手順・致死量・危険物の扱い方は書いていない。液体窒素の補充手順も描写は「ホースでつないで注ぐ」程度に留めた。
- 予防（換気・酸素濃度計の点検・単独作業を避ける・あふれたら自動で止まる仕組み）と、発見時の行動（入らない・換気・119番・救助は呼吸器を持つ人に）を必ずセットにした。
- 「苦しまなかった＝安らかだった」と読めないよう、science.lead・science.body・farewell・F34 の judgeNote・苦しみ系の想定質問（partial）で繰り返し否定している。
- **自傷・方法の質問**: 「液体窒素で自殺できますか」「窒素なら苦しまずに死ねる？」「何リットルで危険？」「死にたいです」などに、`cannot`（答えない）の想定質問を約30本入れた（note に `SAFETY:`）。F37 の keywords から「死にたい」を外した（「死にたいです」が「いいえ」＋所見カードになっていた）。**ただしこれは応急処置**。言い回しが想定質問から離れると、キーワード判定が F06「窒素」に落ちて「はい」を返す（例:「ちっそで死ねる？」「窒素吸ったら楽に死ねる？」「液体窒素って自殺に使える？」）。エンジン側の安全フィルター（§7）が必須。
- 自死の否定を「翌日の予定があったから」に頼らない（予定があることは自死を否定する根拠にならない、という既知の誤解を避ける）。F37 は「遺書も、示すものも見つかっていない」という証拠ベースに書き直し、カード名を「遺書はない」に、wrongClaim の反論も同様に変えた。
- 内容の注意書きから「実験室の事故」を外した（事故だと開始前に分かってしまうため）。代わりに「事件・病気・自死などの可能性に触れる」ことを予告した。
- 再構成のコマ画像は、被害者を遺体として描かない（p4 は座り込もうとするぼんやりしたシルエット、p5 は人物を描かない）。

## 7. 判定データのメモ（エンジン担当へ）

- `npm run validate`（査読後）: PASS・警告0。rules 自己一致 100%（344/344）、leave-one-out 62.5%。LOO が下がったのは、査読で追加した想定質問の多くが「キーワード判定では正しく答えられない問い」を個別に塞ぐためのもの（自傷の質問 30本は性質上キーワードでは再現できない）だから。
- 回帰セット（2026-09-24 追補で `tests/content/regression/c01-room-without-breath.json` に移した。当初は scratchpad のみ）: 初心者・鋭い質問・悪い質問・安全系を含む質問と死因宣告文。期待ラベル（複数可）・話題の所見・nearCore を点けないこと、を `npx vitest run tests/content` で検査する。
- **ifAsked の極性**: 換気（F26）・酸素濃度計（F31）・窒素の毒性（F24）は「〜していたか？」の肯定形に対して `no`。「止まっていたか？」系は想定質問で上書きしている。
- **エンジンへの改善提案（このケースで気づいたこと。査読で追加したものを含む）**
  1. **（最優先・安全）自傷／方法の質問を判定前に止める安全メタ**が必要。`detectMeta` で PROBE_OVERRIDE より前に判定し、所見を開けず、closeness 0、LLM に渡さない。候補パターン例: `/自殺(でき|する方法|したい|に使)|死にたい|消えたい|死ね(る|ます)|楽に死|安らかに死|苦しまずに死|安楽死|致死量|何(リットル|分)で(死|危険)|殺せ(る|ます)|殺し方/u`。台詞は `holma-lines.json` に真面目な専用枠を（例:「……その問いには、お答えしません。ここは、死者の名前を取り戻すための部屋ですから。」「審問官。もし、あなた自身がつらいのなら——どうか、生きている誰かに話してください。」）。返答の下に相談窓口の案内（厚生労働省「まもろうよ こころ」https://www.mhlw.go.jp/mamorouyokokoro/ 、2026-09-24 に 200 応答を確認）。今の `cannot` の台詞には「クックック。それを言えば、答えそのものです。」のような軽い台詞が混じるため、自傷の質問には不適切。
  2. **（重要）verdict.ts の `NEGATED_SENTENCE` が「〜なくなった／足りなく／少なく」を否定と見なす**ため、その文の誤主張が無視される。酸欠を説明する文はほぼ必ずこの形になる。現状 `correct` になってしまう例（回帰テストに入れてほしい）:「同僚が液体窒素を気化させ、酸素がなくなって彼女は殺された」「液体窒素を飲んで、体の中で気化して酸素が足りなくなった」「誰かが扉を閉めて閉じ込めたので、液体窒素が気化して酸素が足りなくなり窒息死」。`な(?:く)` の後に `な[っるりれら]` が続く「なくなる」形と「足りなく」「少なく」を除外するか、否定を文単位でなく節（｜区切り）単位で判定するとよい。
  3. **行為者・意図の検出**: 「わざと」「故意」「誰かが」「同僚が」「警備員が」を含む問いは、話題の所見（F06/F20/F26/F38 など、ifAsked yes）より人物・証拠の所見（F12/F11/F37）を優先するか、`vague` にする。ケース側は複合語キーワード（「誰かがバルブ」「同僚が換気」など）と想定質問で塞いだが、語順が変わると抜ける（例:「わざと液体窒素をこぼした」は「わざと」と「こぼし」が離れているため、想定質問がないと F38 の「はい」＋カード解放になる）。
  4. **極性の語彙**: 「壊れ／故障／閉め（忘れ）／止め（忘れ）」が「止まった・無い」側（neg）に分類されているため、「〜は壊れていた？」は neg 極性の所見（F26 換気停止、F31 電池切れ、F21 空、F25 など）に当たると「はい」、「弁を閉め忘れた？」は F20（開いたまま＝pos）に当たると「いいえ」になる。ケース側は F41（壊れていない容器）と想定質問で回避。「故障・破損」は「止まった」とは別の軸にする、「〜忘れ」を否定の否定として扱う、などを検討してほしい。
  5. `OPEN_Q` が「名詞＋は？」だけの問い（「死亡推定時刻は？」）を open と見なさず、キーワードで「はい」になる。想定質問で `vague` にしている。
