## 2026-09-24

### 進め方
- ユーザーの経験則「詳細設計書で縛らない方が質が上がる」に従い、設計書は参考資料として扱い、絶対条件と体験目標だけを拘束とした。創作・画面・演出の方針は `docs/design-bible.md` に自分で決めて記録した。

### 世界観と人物（オリジナル）
- 舞台「零番安置室」、案内役「ホルマ」（白ウサギの剥製標本）、被害者の魂は「割れたガラスの破片でできたシルエット」として表現。所見を得るたびに破片が灯り、解決で名前と肖像が戻る。
- 「嘘をつけない・訊かれたことにしか答えない」という部屋の掟を、AIの制約（余計なことを言わない、真相を漏らさない）の物語上の理由にした。

### 判定AI
- Jev は OpenRouter の `typesafe/jev-1.13`（`POST /api/alpha/decisions`）。2026-09-24 に1回だけ実際に呼んで返り方を確認した（0.87秒、$0.00003）。choice は `criteria` にオブジェクト、score は `criteria` に配列、noul は確率を返す。
- 本番の既定は「Jev 判定 → 定型文（FAST PATH）」。1質問あたり約0.005円で、ユーザーの目標「0.1円以下」を大きく下回る。LLM による言い換えは任意（比較用のモードとして残す）。
- ユーザーの「開発中は Codex App Server で進める」は、開発中の文章生成（LLM）を Codex のサインイン枠で動かせるようにする、と解釈した（`LLM_PROVIDER=codex`）。判定そのものは Jev が非常に安いので、開発中から Jev を使える構成にした。
- 外部APIが使えないときは、事前登録の想定質問とキーワードによる「rules」判定に自動で落とす。オフライン版（静的配信）も rules で動く。

### 秘密の守り方
- 真相・全所見・正解条件はサーバーにだけ置き、ブラウザには解放済みの所見と署名つき進行トークン（HMAC）だけを渡す。静的配信版では秘密は守られない（オフライン体験・QA用と割り切る）。

- 画像の中に文字は入れない。読ませる文字はすべてDOM。

### 事件
- 3件: 液体窒素による酸素欠乏（化学・生理学）、心臓震盪（物理・生理学）、低体温症と矛盾脱衣（生理学・法医学）。事故・予防の観点で書き、致死量や手順は書かない。
- 科学解説は公的機関・学会・論文で裏を取り `sources` に記録。人の専門家確認が済むまで `reviewStatus` は `ai-reviewed` のままにし、画面に「専門家確認前の下書き」と表示する。

- 自傷の打ち明け・死に方／致死量など方法の質問・人を傷つける方法の質問は、**判定より前に規則で止める**（`server/engine/safety.ts`）。モデルには送らない。返事は冗談なしの真剣な一言＋相談窓口カード（厚生労働省「まもろうよ こころ」）。スタンプ演出は出さない。質問文は記録に残さない。

- 既知の限界: 「凍死は苦しくないのですか？」のような文は、被害者への問いと「楽に死ねるか」の区別がつかない。安全側に倒したまま。

### 判定 AI の既定
- 本番の既定は **`jev`（Jev 判定＋書き溜めた台詞）**、候補は **`all+prior`**、判定文は **v2**。823問の汎化テストで正答率 91.1%（rules 73.4%）、1問 約0.045円（$0.0003）、p50 約0.33秒。
- LLM による言い換えは比較用に残すだけ（遅く、事実を足すことがある）。LLM だけで判定する `llm` は使わない（正答率が低く、話を作る）。
- 死因宣告でモデルの一致を採るのは確率 0.85 以上のときだけ。

## 2026-09-26 題名を『リトマス審問』に変更

- くられ先生から、「ジェーンドゥの死因」は薬理凶室さん側ですでに企画があり重なる、との返信。監修は引き受けていただける方向。
- 新しい題名は **『リトマス審問』**（英字サブタイトル LITMUS INQUEST : YES OR NO）。リトマス試験紙が赤か青かの2択で答えを示すのと、はい／いいえで真相を見分ける遊びを重ねた。科学の言葉なので監修との相性もよい。同名のゲームは検索で見当たらなかった（商標は J-PlatPat で第9類・第41類を要確認）。
- 変えたのは題名だけ。作中の「ジェーン・ドゥ」という呼び名は、変えるべきか先生に確認中。
- ロゴは「の」がない題名でも2段に組めるようにした（カナ＋末尾の漢字語: リトマス／審問）。ロゴ用フォントの先読みも 審・問 の字の分割ファイルに差し替え。
- 一般の人が作る問題（UGC）は、死を扱わない水平思考の問題にする方針。その場合も「リトマス」を共通の看板にして、公式の死因事件＝「審問」、一般の問題＝別の名前のモード、と分ける案を持ち主に提示。
- ロゴの組み直し（同日、持ち主の指摘「リトマスに迫力がない・リズムがない・単調」）: 原因は字形と構成。「ジェーンドゥ」は濁点・長音・小書き文字で字の大きさと密度に変化があり、「の」の傾いた札が 大→小→特大 の拍を作っていた。「リトマス」は画数の少ない字が同じ大きさで4つ並ぶだけで軽く、「の」も無いので2段が同じ幅の四角い塊になり動きが消えた。5案（「の」の位置に試験紙の札／字ごとに大きさと傾きを変える／試験紙の帯／審問を判子に 赤・緑）を試作して比較し、**「リトマス」をリトマス試験紙に刷る案**を採用: 黒文字を赤｜青に色が分かれた紙片に載せ、ロゴ全体と別の角度に傾け、「審問」を大きくして紙片の下端に重ねる。入場時は白い紙に赤と青が両端から染みて（酸・塩基の反応）、そのあと「審問」が落ちて止まる。動きを減らす設定では止まった完成形のみ。
