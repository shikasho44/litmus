# リトマス審問（旧題: ジェーンドゥの死因） — 設計の正本（Design Bible）

作成 2026-09-24。並行して作る全員（人もAIも）がこのファイルを基準にする。
データの形は `shared/case-schema.ts`、画面とサーバーの約束は `shared/api.ts` が正本。

---

## 0. 一行で

**「固定された正確な世界を、AIを使って自由に探索できる推理ゲーム」。**
名前のない魂（ジェーン・ドゥ）の死因を、はい／いいえの質問で暴き、審問で彼女の「記憶のノイズ」を論破し、最後に彼女の名前と、その死の裏にある科学を持ち帰る。

体験の芯は3つ。

1. **訊く快感** — 自由に打った質問に、芝居がかった案内役が一瞬で「はい」「いいえ」を叩きつける。核心に近づくと画面が応える。
2. **論破する快感** — 集めた所見を弾にして、間違った記憶を撃ち抜く（ダンガンロンパの議論パートの手触りを、独自の形で）。
3. **知って帰る満足** — 解決後に「なぜそうなるのか」を図解で理解し、確認テストで定着させる。

トーン: 知的、少し不穏、上品。ホラーに寄せすぎない。医療アプリにしない。血・グロ描写はしない。

参考にするのは**ダンガンロンパの「演出の文法」**（大胆な斜めの構図、カットイン、極太の文字、ポップで毒のある配色、議論を撃ち抜く爽快感、コマ漫画で真相を組み直す締め）。**キャラクター・名称・ロゴ・楽曲・固有の画面デザインは一切借りない。** 既存の「ジェーンドゥの死因」動画シリーズのキャラクター・絵・物語・問題文も使わない（名称と基本ルールのみ）。

## 1. 世界観

### 零番安置室（れいばんあんちしつ）
生と死のあいだ、午前0時にだけ開く安置室。死因が定まらないまま死んだ者は名前を失い、「ジェーン・ドゥ」としてここへ流れ着く。死因が明らかになるまで、魂は先へ進めない。

プレイヤーは新任の **死因審問官（あなた）**。顔も名前も出さない（プレイヤー自身）。

### 部屋の掟（ゲームのルールを世界の理屈にする）
- 管理人は**嘘をつけない**。
- 管理人は**訊かれたことにしか答えない**。訊かれていないことを教える義理はない。
- 答えは原則「はい／いいえ／関係ない／一部そう／今は答えられない／もう少し具体的に」。
- 死因を宣告するのは審問官自身の口。管理人が答えを言うことはない。

→ AIが余計なことを言わない・真相を漏らさない、という技術的な制約が、そのまま物語上のルールになる。

## 2. 登場人物

### ホルマ（案内役・ゲームマスター）
零番安置室の管理人を名乗る、**白ウサギの剥製標本**。ホルマリンの瓶から這い出てきた、と本人は言う。

- 見た目: 子どもくらいの背丈の白ウサギ（剥製らしい縫い目が首と片耳にある）。サイズの合わないぶかぶかの白衣（袖をまくっている）。片目は琥珀色のガラス玉（剥製の義眼）、もう片目は黒いボタン。片耳に標本タグ「No.0」を虫ピンで留めている。首元に**ホルマリン色（黄緑）の蝶ネクタイ**。手には指示棒を兼ねた、細長い銀のプローブ（メスではない）。木箱（標本箱）を踏み台にして立つ。
- 色の約束: 白衣の白、黄緑 #C6FF3D の蝶ネクタイ、琥珀色のガラス目 #FFB020。（当初は赤い目だったが、他作品の案内役マスコットを連想させるとレビューで指摘され、2026-09-24 に琥珀色へ変更）
- 性格: 慇懃無礼で芝居がかった司会者。真実をすべて知っていて、それを掟のせいで言えないことを楽しんでいる。意地悪だが、最後には死者に対して誠実。
- 口調: 丁寧語ベースで語尾を伸ばす。「〜ですねェ」「〜ですとも」「さァ」。笑いは「クックック」「ククッ」。一人称は「私（わたくし）」、プレイヤーは「審問官」「あなた」。
- 決め台詞: 「さァ——解剖（しらべ）を始めましょう」／審問開廷「開廷ですとも！」
- 4表情（立ち絵）: `normal`（薄笑い）/ `laugh`（大口で高笑い）/ `surprised`（耳が跳ね上がる）/ `serious`（真顔。真相・別れの場面）
- ホルマは**答えを言わない**。ただし審問官が核心に近づくと、隠しきれずに反応する（`nearCore` 演出）。

### ジェーン・ドゥ（各事件の被害者の魂）
名前も顔も失った魂。**割れたガラス（ステンドグラス状の破片）でできたシルエット**として現れる。
- 所見を得るたびに破片が1枚ずつ灯り、彼女の姿（肖像）が少しずつ見えてくる（青い単色で）。
- 死因宣告が通ると全破片がつながり、フルカラーの肖像と**名前**が戻る。「ジェーン・ドゥ #01」→「白石 澪」。
- 話し方: 明朝体。断片的で、たまに文字化けのように揺れる。審問では「間違った記憶（ノイズ）」を本気で信じて主張する。
- 最後に彼女自身の言葉で別れを告げる（`victim.farewell`）。

## 3. ゲームの流れ

```
タイトル
 └ 初回のみ: プロローグ（ホルマが掟と遊び方を芝居で説明。スキップ可）
事件ファイル（事件選択。足首タグ＝トゥタグ型のカード）
 └ 事件の導入（発見現場のナレーション → ジェーンの破片が現れる → ホルマ「解剖を始めましょう」）
   └ 捜査パート（自由質問）
       ├ 所見カード獲得 → ジェーンの破片が灯る
       ├ 科学メモ解放
       ├ ヒント「ホルマの囁き」×3（事前作成）
       └ 「審問を開く」
   └ 審問パート（死因審問 INQUEST）
       ① ノイズ・ブレイク（議論）: ジェーンの誤った記憶を所見で撃ち抜く（1〜2ラウンド）
       ② 死因宣告（VERDICT）: 自由記述で「何が起きて、なぜ死んだか」
       ③ 真相再構成（RECONSTRUCTION）: 5コマ漫画の空白を埋める → ホルマが全貌を語る
   └ 身元回復（破片が全部つながり、名前が戻る。彼女の別れの言葉）
   └ 科学解剖（SCIENCE AUTOPSY）: この事件の科学（図解）
   └ 記憶の定着（確認テスト 2〜3問、間違えても再回答可）
   └ CASE COMPLETE（審問官ランク S/A/B/C と記録）
```

### 3-1. 捜査パート
- 入力は自由文。Enter で送信（IME変換中の Enter は送信しない）。複数質問は分割して順に答える（最大3）。
- ホルマの返答: 巨大な**判定スタンプ**（はい／いいえ／関係ない／一部そう／答えられない／具体的に）＋短い一言。スタンプは色だけでなく文字で意味が分かること。
- 所見獲得時: カットイン「所見入手」→ カードが捜査ノートへ飛ぶ → ジェーンの破片が灯る。
- 初めての人向けに、入力欄の上に**質問の例チップ**（`intro.starterQuestions`）。押すと入力欄に入る（送信はしない）。
- 捜査ノート: タブ「所見」「質問ログ」「科学メモ」。所見はカテゴリ（人物・場所・時間・物品・身体・環境・証拠・科学）で並ぶ。
- 画面上部: 事件名、質問数、経過時間、ヒント、「審問を開く」。
- **ヒント**は3段階。使うとランクが下がる（使ったことは記録されるが責めない）。
- 審問はいつでも開ける。所見が少ないうちはホルマが「……証拠がずいぶん心許ないようですが？」と確認する。

### 3-2. 審問パート（INQUEST）
画面の空気が変わる。BGM が審問曲へ。背景は「審問の間」。

**① ノイズ・ブレイク**
- ジェーン（とホルマ）の発言が、画面を斜めに流れる帯として1つずつ現れる（ループする）。
- 発言中の**ノイズ（[[ ]] で囲まれた語）**が発光している。所見カードを選んで、そのノイズを撃つ。
- 正解: 「反証！」のカットイン → ノイズがガラスのように砕ける → ジェーンの記憶が一つ正される。
- 不正解: **集中力**（5つ）が1減る。ホルマが茶化す。同じラウンドで2回外すとヒント。
- 必要な所見を持っていない場合: 「ホルマに泣きつく」で所見を1枚もらえる（ランク減点）。**詰まない**ことを最優先。
- 集中力0: 審問中断 → 捜査へ戻る（それまでの所見は失わない）。
- 操作: PC はクリックで帯のノイズを選ぶ → 所見を選ぶ → 撃つ。スマホは帯がゆっくり流れ、タップで一時停止してから選べる。キーボードだけでも遊べる（Tab/矢印/Enter）。

**② 死因宣告**
- 「彼女に、何が起きたのか。なぜ死んだのか。あなたの言葉で。」
- 自由記述。答えの要素（`answerElements`: 直接死因／原因となった出来事／科学的な仕組み／決定的な状況 など）ごとに判定。
- 結果は4段階: `correct`（正解）/ `almost`（ほぼ正解＝核は合っている。足りない要素をホルマが遠回しに指摘）/ `missing`（重要な要素が不足）/ `wrong`（推理を続ける必要がある）。
- 要素チェックリストを表示（「直接死因 ✔」「なぜ ？」）。どの要素が足りないかは分かるが、**答えは言わない**。
- 何度でも挑戦できる（回数は記録）。

**③ 真相再構成**
- 5コマ前後の漫画。いくつかのコマが空白。候補（3〜4択）から正しいコマを選んで埋める。
- 全部埋まると、ホルマが事件の全貌を語りながらコマを順に照らす（`reconstruction.finale`）。

### 3-3. 身元回復
- 破片が中心へ集まって一枚の肖像に。モノクロ→カラー。名前・年齢・職業が刻まれる。
- ジェーン（もう名前がある）の別れの言葉。ホルマは真顔で見送る。

### 3-4. 科学解剖（SCIENCE AUTOPSY）
事件の科学を、原因→科学現象→人体への影響→結果 の因果の鎖として理解させる。
構成（`science`）: 今回の死因 / 因果の鎖 / 何が身体で起きたのか / なぜこの状況で起きたのか / 事件中の伏線（どの所見が何を意味していたか） / 科学的メカニズム（図解つき） / よくある誤解 / 身近なところでは / 覚えて帰るポイント / 身を守るために / 参考資料。
- 図解は `science.diagrams`（levels / ecg / ratio）をコードで描く。文字はDOM/SVG。
- 危険情報への配慮: 致死量、実行手順、危険物の調製方法、人を傷つける再現手順は書かない。「なぜ起こるか」「どう防ぐか」を中心にする。
- 画面の隅に「この解説は作成中の下書きです（専門家確認前）」を `reviewStatus` が `human-reviewed` でない間は表示。

### 3-5. 記憶の定着（確認テスト）
2〜3問の4択。間違えても解説を読んで再回答できる。全問正解で CASE COMPLETE。

### 3-6. 審問官ランク
スコアを主役にしない。結果画面で控えめに見せる。
- 要素: 質問数（少ないほど良いが、所見の数とのバランス）、重要質問率（所見を得た質問の割合）、ヒント使用、ノイズ・ブレイクの失敗、死因宣告の回数、泣きつき回数、所要時間。2026-09-27 から **ゲームオーバー**（その事件を解くまでの回数。1回12点、最大36点）と **確認テストのやり直し**（1回2点、最大8点）も減点する。
- S/A/B/C の4段階と、ひとことの称号（例: 「一撃の審問官」「慎重な観察者」）。
- **ミスはその場で見せる**（2026-09-27）: 囁き・撃ち損じ・泣きつき（新しい所見をもらったときだけ）・死因宣告の失敗・確認テストのやり直しで、その操作の横に小さな「減点 −n」の札が約1秒出て消える。n はその事件の難易度でランク計算が実際に引く点（上限に届いたあとは差分、0 なら出さない）。読むべき文字には重ねない。ゲームオーバーと審問中断は、その画面の札で同じく「減点 −n」を示す。

#### 名探偵度数（2026-09-27 追加）
監修のくられ先生の感想「ミスにペナルティの実感がない。内部で減点して累計スコアを出し、解決時に探偵レベルを見せ、名探偵度数の称号バッジがあるとよい」への答え。
- **獲得度数**（1回の解決）＝ 事件スコア（上のランク計算の 0〜100 点）× 難易度の倍率（見習い 0.6 ／ 審問官 1.0 ／ 教授 1.4）を四捨五入 ＋ S+ ボーナス 10。
- **名探偵度数** ＝ 事件ごとの最高獲得度数の合計。遊び直しは、その事件の最高を超えた分だけ増える（易しい事件の周回では稼げない）。
- **称号**（絶対値のしきい値。事件が増えると上が届くようになる）: Lv1 駆け出し探偵（1〜）／ Lv2 一人前の探偵（120〜）／ Lv3 腕利き探偵（240〜）／ Lv4 名探偵（360〜）／ Lv5 伝説の名探偵（480〜）。0 は「まだ称号なし」。今の3事件では最大 450 で Lv4 まで。
- **バッジ**: 画像を使わない CSS のメダル（ギザギザの縁の中に黒い円とレベルの数字）。銅 → 銀 → 金 → ホルマリン → 虹（Lv5）。色はトークンだけから作る。
- **見せ方**: 結果画面ではランクの判子の下に一枚のカード（獲得 +N と内訳、この事件の最高を更新したか、累計のカウントアップ、バッジ、次の称号までのバー）。称号が上がった回だけ「ランクアップ！」の札が短く出る。カウントは画面に入ってから始まり、タップかキーで終わる。動きを控える設定では最初から完成形。事件ファイルの見出しに小さなメーター（押すと遊び方の説明ページ。スマホでは何も始めていない初回だけ隠し、最初の事件の開始ボタンを画面内に残す）、事件タグの BEST 判子の下にその事件の最高度数。共有文にも名探偵度数と称号を入れる。
- 主役はあくまでランクの判子。度数はその下の控えめな一枚で、数字の大きさも判子より小さく保つ。


### 3-7. 難易度・任意の議論・ゲームオーバー（2026-09-25 追加）
- 事件を始めるときに難易度を選ぶ。見習い（選択式・やり直し10回・失敗したら審問の最初から）／審問官（穴埋め式・3回・事件の最初から）／教授（自由記述・3回・事件の最初から）。
- ノイズ・ブレイクは任意。撃ち抜くと死因宣告の手がかり（選択肢が1つ消える／空欄が1つ埋まる／要素が1つ明かされる）がもらえる。
- やり直しを使い切ると、謎は謎のまま彼女が消えていき、タイトルへ戻る。審問官・教授では失敗した回の記録は消えるが、ゲームオーバーそのものはその事件を解くまで数えられ、事件スコアから1回12点（最大36点）引かれる（2026-09-27、§3-6 名探偵度数）。
- S かつ全ラウンドを自力で撃ち抜くと S+。
- CASE 01 の初回は、実際の画面で案内するチュートリアル。

## 4. 画面設計

### 4-1. レイアウトの原則
- **PC（横長）**: 16:9 の舞台を中心に据えた映画的な画面。舞台の上に背景・ホルマ・ジェーンの破片・スタンプ・カットイン。下に会話欄と入力欄。左にたためる捜査ノート。
- **スマホ（縦持ち）**: 上に舞台（高さ約38%：ホルマとジェーンの破片、スタンプ）、中央に会話ログ、下に入力欄（キーボードが出ても入力欄が隠れない）。捜査ノートは下から出るシート。
- 画面の高さは `visualViewport` 基準（iPhone のツールバー対策）。セーフエリア（`env(safe-area-inset-*)`）を守る。
- 横スクロールは出さない。最小幅 320px で破綻しない。

### 4-2. ビジュアル言語
- 配色トークン:
  - `--ink` #0B0D12（背景の黒。わずかに青）
  - `--ink-2` #141821 / `--ink-3` #1E2430（面）
  - `--bone` #F2EFE6（紙・文字）
  - `--formalin` #C6FF3D（主役の差し色。はい／所見／進行）
  - `--alarm` #FF2E63（いいえ／警告／審問）
  - `--cyan` #3DE0FF（ジェーンの破片・記憶）
  - `--amber` #FFB020（一部そう）
  - `--violet` #9B6BFF（答えられない）
  - `--mute` #8A93A6（関係ない・補助文字）
- 質感: ハーフトーンの網点、標本ラベル、トゥタグ、斜めの警告ストライプ、走査線、ガラスの破片、手書き風の赤い丸。
- 構図: 斜め（-6°〜-12°）の帯とカットイン。止め絵に動きを与える小さな揺れ。
- 文字:
  - 見出し・スタンプ・カットイン: **Dela Gothic One**
  - 本文・UI: **Zen Kaku Gothic New**（400/500/700）
  - ジェーンの言葉: **Shippori Mincho B1**
  - 英字の飾り（YES / NO / CASE 01）: **Anton**
  - 数値・記録・ラベル: **JetBrains Mono**
- モーション: GSAP。カットインは 0.35〜0.6 秒。スタンプは叩きつけ（拡大→縮小＋わずかな回転＋画面の揺れ）。`prefers-reduced-motion` と設定の「演出を控えめに」で揺れ・フラッシュ・グリッチを止める。**点滅は1秒に3回を超えない。**
- 背景の生きている感じ: 軽い WebGL/Canvas のノイズ（ホルマリンの液体が揺れるような緑の靄、漂う粒子）。低性能端末では自動で止める。

### 4-3. 判定スタンプ
| 答え | 文字 | 英字 | 色 |
|---|---|---|---|
| yes | はい | YES | formalin |
| no | いいえ | NO | alarm |
| partial | 一部そう | PARTIAL | amber |
| irrelevant | 関係ない | IRRELEVANT | mute |
| cannot | 今は答えられない | CLASSIFIED | violet |
| vague | もう少し具体的に | REPHRASE | bone |

### 4-4. 音
WebAudio の合成音（音源ファイルなし）。初回のユーザー操作で開始。
- BGM: `title`（オルゴール＋低いドローン）/ `investigation`（静かなミステリー。ピチカートのベース、時計の音、ビブラフォンの和音）/ `inquest`（テンポの速い四つ打ち＋うねるベース＋スタブ。審問の高揚）/ `truth`（ゆっくりしたピアノ風パッド）/ `science`（穏やかなアンビエント）
- 効果音: 文字送りの声（ホルマは高め・ジェーンは澄んだ音）、スタンプ、所見入手、ガラスの砕ける音、カットインの風切り、決定、キャンセル、警告、開廷の木槌、心音。
- 設定: BGM音量・効果音音量・全体ミュート。

### 4-5. アクセシビリティ
- すべての操作がキーボードで可能。フォーカスリングを消さない。
- ホルマの返答は `aria-live` で読み上げ。
- 文字サイズ設定（標準／大／特大）。
- 色だけに意味を持たせない（スタンプは文字＋色）。
- 演出を控えめにする設定。

## 5. AIのしくみ

### 5-1. 役割分担
- **コード**: ルール。所見の解放、ネタバレ段階、正解条件、回数制限、ランク。
- **Jev**（`typesafe/jev-1.13`、OpenRouter `POST /api/alpha/decisions`）: 判断。質問の分類、はい/いいえ、関連所見の選択、核心への近さ、推理文の要素判定、LLM出力の検査。文章は書かない。
- **LLM**（任意）: 表現。ホルマの口調で一言を言い換えるだけ。答えの中身は決めない。
- **定型文**（`content/holma-lines.json`）: 既定の返答。事前に書いた多数の言い回しから選ぶ。

### 5-2. パイプライン
```
質問
 → 正規化（全角半角・かな・記号・分割・否定検出）
 → 候補抽出（所見のキーワード＋想定質問との類似度、上位8件）
 → 判定（mode に応じて rules / Jev / LLM）
 → 規則（開示してよい所見か、spoilerLevel、requires）
 → 返答（FAST PATH: 定型文 ／ LLM で言い換え）
 → 検査（mode C: Jev が漏れ・矛盾を確認。NG なら1回だけ作り直し、だめなら定型文）
 → 所見の解放・トークン更新・計測ログ
```

### 5-3. モード（比較できるようにする）
| mode | 中身 | 用途 |
|---|---|---|
| `rules` | 想定質問との類似＋キーワード。外部APIなし | オフライン・QA・障害時の退避先 |
| `jev` | Jev 判定 → 定型文（FAST PATH） | **本番の既定**。1質問 約$0.00003 |
| `jev+llm` | Jev 判定 → LLM が言い換え | 表現の比較 |
| `jev+llm+check` | Jev → LLM → Jev 検査 | 設計書の MODE C |
| `llm` | LLM が全部（真相を渡して JSON で答える） | 設計書の MODE A（比較の基準線） |

- 障害（タイムアウト・429・5xx）は再試行1回 → それでもだめなら `rules` に落として返す。プレイヤーには「通信が不安定なため簡易判定で答えています」と小さく出す。ゲームデータは失わない。
- 1日の費用上限（`DAILY_COST_LIMIT_USD`）を超えたら `rules` に落とす。

### 5-4. プロバイダ
- `DECISION_PROVIDER`: `jev`（OpenRouter）/ `rules`
- `LLM_PROVIDER`: `openrouter`（安価なモデルを `LLM_MODEL` で指定）/ `codex`（開発用: Codex app-server 経由。ChatGPT のサインイン枠で動く）/ `none`
- APIキーはサーバーの環境変数だけ。ブラウザへは絶対に出さない。

### 5-5. 秘密の守り方
- 事件データの秘密部分（真相・全所見・想定質問・正解要素・再構成の正解・科学解説・被害者の名前）はサーバーにだけ置く。
- ブラウザが持つのは、公開情報と、解放済みの所見と、署名つきの進行トークン（HMAC）。
- 解決（死因宣告が通った）トークンを持っている場合だけ、真相と科学解説を返す。
- 静的配信版（`build:static`）は判定エンジンと事件データを同梱する（オフライン・QA 用）。この場合は秘密は守られないことを README に明記。

### 5-6. 計測とベンチマーク
- 1ターンごとに `TurnTrace` を記録（各段階の時間、トークン、費用、候補、判定、フォールバック）。
- `npm run bench` で想定質問（1事件50〜100問、人が付けた正解ラベル）を各 mode で流し、正答率・所見一致率・分類精度・漏洩率・一貫性・平均/中央値/P95/P99・1問あたり費用・やり直し率を出す。結果は `bench/reports/` に JSON と HTML。
- 管理画面（`admin.html`、開発時または `ADMIN_TOKEN`）で事件の検査結果・ベンチ結果・直近のトレースを見る。

## 6. 事件（3件）

すべて架空。実在の人物・事件・団体と無関係。科学の説明は公的機関・学会・大学・論文で裏を取り、`sources` に記録する。`reviewStatus` は人が確認するまで `draft-ai`/`ai-reviewed`。

### CASE 01「息のない部屋」THE ROOM WITHOUT BREATH（難易度1・化学/生理学）
- ジェーン・ドゥ #01 → **白石 澪（しらいし みお）** 29歳、大学の特任研究員（細胞生物学）。
- 発見: 朝6時過ぎ、警備員が大学棟地下の「試料保管室」で発見。棚にもたれて床に座り、眠っているように見えた。外傷なし、争った形跡なし。部屋には窓がない。
- 真相: 深夜0時台、保管タンク（液体窒素で細胞を凍結保存する容器）の残量警報がスマホに届き、彼女は一人で補充に来た。補充中に大型の液体窒素容器から窒素ガスが大量に気化。夜間は省エネで換気が止まり、重い扉は自動で閉まっていた。壁の酸素濃度計は電池切れで警報が鳴らなかった（＝「壊れた機械」）。空気中の酸素が窒素に置き換わり、**酸素欠乏**で意識を失い死亡。息苦しさは二酸化炭素で感じるため、酸素が減っても苦しさで気づけなかった。
- 伏線の例: 床の霜・白い靄の跡、補充ホース、スマホの警報通知 0:52、止まった換気、電池の切れた酸素濃度計、容器の圧力計、同僚との口論（無関係）、飲みかけのコーヒー（無関係・毒なし）。
- 科学: 空気の組成（窒素78%・酸素21%）、液体→気体で約700倍の体積、閉じた小部屋での置換、呼吸の欲求は主に血中CO2が駆動、酸素18%未満が法令上の酸欠、濃度ごとの症状、救助者の二次災害、酸素濃度計と換気と単独作業の禁止。誤解: 「窒素は毒」「苦しくなるから気づける」「ドライアイスも同じ仕組み」（CO2 は別の害がある）。

### CASE 02「夕暮れの白球」THE BALL AT DUSK（難易度2・物理/生理学）
- ジェーン・ドゥ #02 → **早瀬 ひより（はやせ ひより）** 18歳、高校3年（ソフトボール部を夏に引退）。
- 発見: 8月の夕方、河川敷の公園。10歳の弟の投球練習に付き合ってキャッチボール中、倒れた。
- 真相: 夕日が逆光で、弟の投げた軟式ボールを捕り損ね、**左胸に当たった**。数歩歩いて「大丈夫」と言い、数秒後に倒れた。外傷はほぼなく骨も折れていない。心臓に持病も構造の異常もない。胸への衝撃が、心臓の拍動の中の**ごく短い「受けやすい瞬間」（心電図のT波の頂上の少し前）**に重なり、**心室細動**が起きた＝**心臓震盪**。近くの公民館にAEDがあったが、使われないまま救急車の到着を待った。
- 伏線の例: 逆光、軟式ボール、左胸、あざがほとんどない、数秒後に倒れた、持病なし、熱中症ではない（水分は取っていた・体温は高くない）、AEDの場所、救急車到着まで約12分。
- 科学: 心臓の電気の流れと心電図、再分極の「受攻期」、強くない衝撃でも起こる、子ども・若者の胸郭は柔らかい、心室細動は電気ショック（AED）でしか戻せない、1分ごとに救命率が下がる、胸骨圧迫とAED。誤解: 「強い衝撃でないと起きない」「意識がすぐ戻れば大丈夫」「AEDは医療者しか使えない」「胸を叩けば治る」。
- 配慮: 未成年の家族（弟）への責めを描かない。「誰のせいでもない」を物語の着地にする。

### CASE 03「雪に残されたもの」WHAT WAS LEFT IN THE SNOW（難易度3・生理学/法医学）
- ジェーン・ドゥ #03 → **椎名 遥（しいな はるか）** 34歳、フリーの山岳写真家。
- 発見: 1月、下山予定を過ぎても連絡がなく、翌日の捜索で登山道から外れた岩の隙間で発見。**上着・手袋・帽子が周囲の雪の上に点々と脱ぎ捨てられ**、本人は薄着で、狭い隙間に潜り込むように体を丸めていた。事件（暴行・強盗）が疑われた。
- 真相: 撮影中にホワイトアウトに巻き込まれ、足首を捻挫して道を外れた。気温は氷点下十数度、強風。体温が下がり続け、**重度の低体温症**に。末期に体が「熱い」と錯覚して服を脱ぐ**矛盾脱衣**と、狭い所へ潜り込む**穴ごもり行動（terminal burrowing）**が起きた。暴行も強盗もない（財布・カメラは残り、足跡は本人のものだけ、外傷は擦り傷程度）。法医学的には胃の粘膜の小さな黒い斑点（低体温症で見られる所見）などが凍死を示す。
- 伏線の例: 点々と脱いだ服、盗られた物なし、足跡は一人分、足首の捻挫、ホワイトアウト、岩の隙間、胃の粘膜の斑点、膝や肘の皮膚の赤み、カメラの最後の写真（午後3時の吹雪の稜線）、魔法瓶のココア（無関係）。
- 科学: 体温調節（震え・血管収縮）、低体温症の段階（中心体温35℃以下、32℃で震えが止まる、判断力の低下）、矛盾脱衣の説明（血管収縮の限界→急な拡張で熱く感じる、体温調節中枢の不全）、穴ごもり、風と濡れによる熱の奪われ方、**夏山や屋内でも起こる**（日本の凍死は屋内・高齢者も多い）。誤解: 「服を脱いでいたら事件」「寒いうちは震え続ける」「お酒で温まる」「冬山だけの話」。

## 8. 技術構成

- Vite 8 + TypeScript 7 + Preact + @preact/signals + GSAP。`base: './'`。
- `shared/` 型と検証（zod）。`server/` 判定エンジン（フレームワーク非依存の純粋な TS。Node でもブラウザでも動く。Node 専用処理は `server/node/` に隔離）。`api/` Vercel 用の入口。`src/` 画面。`content/` 事件データと台詞。
- 開発サーバー: Vite プラグインで `/api/*` を同じエンジンに接続（`vite dev` と `vite preview` の両方）。
- 本番: Vercel（`api/router.ts`、Node ランタイム）。環境変数 `OPENROUTER_API_KEY`, `SESSION_SECRET`, `DECISION_PROVIDER`, `LLM_PROVIDER`, `LLM_MODEL`, `PIPELINE_MODE`, `DAILY_COST_LIMIT_USD`, `ADMIN_TOKEN`。
- 静的版: `vite build --mode static` で埋め込みエンジン（rules）を同梱。
- 設定値: `src/config/app.ts`（`APP_TITLE`, `GAME_TITLE`, `SUBTITLE`, `COPYRIGHT_NOTICE`, `OFFICIAL_RELEASE_ENABLED`, `CONTACT_URL`, `ANALYTICS_ID`）を `VITE_*` 環境変数で上書き可能。`OFFICIAL_RELEASE_ENABLED=false` の間は「PREVIEW」表記と `noindex`。
- セーブ: `localStorage`（try/catch 必須）。事件ごとに質問ログ・所見・科学メモ・ヒント・経過時間・審問の進み具合・トークン。途中で閉じても再開。
- 検証: `npm run typecheck && npm test && npm run validate && npm run build && npm run qa && npm run qa:mobile`。
